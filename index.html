Unit 1

Introduction to Tailwind CSS and Core Utilities

Learn what Tailwind is, set it up, and style elements with colours, text, spacing, borders, shadows and states.

1.1

What is Tailwind CSS? (utility-first CSS)

Tailwind CSS is a CSS framework that gives you small ready-made classes. Each class does one job only. You write these classes directly in HTML, so you rarely need your own CSS file.

Easy example: Normal CSS is like cooking from scratch. Tailwind is like a kitchen with labelled jars (salt, sugar, chilli). You just pick the jars you need.

ClassJob
bg-lavenderLight purple background
text-lavender-deepDark purple text
font-boldBold text
px-3 py-1Padding left/right and top/bottom
rounded-fullPill shape
1.2

Advantages over traditional CSS

Both buttons below look the same. The first needs a CSS class written by hand. The second only uses Tailwind classes.

  • No naming headache. You don't invent names like .btn-wrapper-2.
  • Faster work. You don't switch between HTML and CSS files.
  • Small final CSS. Only the classes you use are added to the output file.
  • Consistent design. Everyone uses the same spacing and colour scale.
  • Easy responsive design. Write md:text-xl instead of a media query.

Downside: the HTML can get long with many classes. We fix this in Unit 3 with reusable components.

1.3

Project setup for plain HTML

Method A: Play CDN. One script line. Good for quick practice only, because it is slow and needs internet.

<head>
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <script src="https://cdn.jsdelivr.net/npm/@tailwindcss/browser@4"></script>
</head>

Method B: Tailwind CLI (proper way). Needs Node.js. Tailwind scans your HTML and builds one small CSS file.

# 1. Install
npm install tailwindcss @tailwindcss/cli

# 2. Create src/input.css with this one line:
@import "tailwindcss";

# 3. Build and keep watching for changes
npx @tailwindcss/cli -i ./src/input.css -o ./src/output.css --watch
<!-- 4. Link the output file in src/index.html -->
<link href="./output.css" rel="stylesheet">

my-site/
├── package.json
└── src/
    ├── input.css    (you write here)
    ├── output.css   (Tailwind makes this, don't edit)
    └── index.html   (your page)

Lab tip: no Node.js on the lab PC? Use Tailwind's standalone CLI (.exe from Tailwind's GitHub releases page). Also install the VS Code extension Tailwind CSS IntelliSense for class suggestions.

1.4

Colours, backgrounds, typography, borders and shadows

Class pattern: what to change + value. text- is for text colour or size, bg- for background, border- for borders, shadow- for shadows, rounded- for corners. Default colours have shades from 50 (lightest) to 950 (darkest), e.g. bg-pink-100.

Use case: a college notice board where colour tells the type of message.

1.5

Margin, padding, width, height and sizing

Padding (p-) is space inside a box. Margin (m-) is space outside it. Rule to remember: 1 unit = 4px, so p-4 = 16px.

ClassMeaning
p-4 px-4 py-2 pt-6Padding: all sides / left+right / top+bottom / top only
m-4 mt-6 mx-autoMargin. mx-auto centres a box.
space-y-4 gap-4Equal gap between children
w-24 w-1/2 w-full max-w-xsFixed width / half / full / maximum width
h-10 min-h-screen size-12Height / full screen height / same width and height
1.6

Hover, focus, active and disabled states

Add a prefix before any class. The style works only in that state: hover: (mouse over), focus: (clicked into or reached with Tab), active: (while pressing), disabled: (button is disabled). Add transition for a smooth change.

Use case: a feedback form. Hover over the buttons, click into the input, and press Tab to move between fields.

Unit 2

Responsive Design, Layouts and Customization

Arrange things with Flexbox and Grid, make pages work on every screen, and create your own theme with dark mode.

2.1

Flexbox utilities and alignment

Flexbox places items in a single row or column. Add flex to the parent. Then justify- controls the main direction (left/centre/right) and items- controls the cross direction (top/middle/bottom). gap-4 adds space between items. Use flex-col for a column and flex-wrap to let items move to the next line.

Use case: navigation bars, button groups, centring something.

2.2

CSS Grid utilities and grid layouts

Grid places items in rows and columns together, like a table. grid grid-cols-3 makes 3 equal columns. col-span-2 makes one item 2 columns wide. gap-3 adds space.

Use case: photo galleries, dashboards, product listings. Flex vs Grid: use flex for one line of items, grid for a full 2-D layout.

2.3

Mobile-first responsive design and breakpoints

Mobile-first means: classes without a prefix are for phones. Then you add prefixes for bigger screens. md:grid-cols-2 means "2 columns from 768px and wider".

PrefixScreen widthTypical device
(none)0px and upMobile
sm:640px and upLarge phone
md:768px and upTablet
lg:1024px and upLaptop
xl:1280px and upDesktop

Try it: make the browser window narrow and wide. The colour bar and the number of columns change.

2.4

Responsive navigation bars, cards, galleries and page layouts

On a phone the links hide behind a menu button (☰). On a tablet and up (md:) the links show in a row and the button hides. The gallery changes from 2 columns to 4.

Use case: almost every website, e.g. a food-ordering site. Make the window narrow and click ☰.

2.5

Positioning, display, overflow and visibility

  • relative on the parent + absolute on the child = place the child at a corner (e.g. a "SALE" tag).
  • sticky top-0 keeps a header stuck while scrolling. fixed sticks to the screen.
  • block, inline-block, flex, grid, hidden change the display.
  • overflow-x-auto lets a long row scroll sideways. overflow-hidden cuts off the extra.
  • invisible hides but keeps the space. hidden removes it completely.
2.6

Typography hierarchy, colours, gradients, shadows and rounded corners

Hierarchy means the reader sees what is most important first: big bold heading, then medium subheading, then normal text. Gradients: bg-linear-to-r from-blush to-peach (r = to the right).

2.7

Theme customization and design tokens

A design token is a named value, like your brand colour or font. You define it once in input.css inside @theme, and Tailwind creates classes for it automatically. Change the token once and every page updates.

This file uses its own pastel tokens. --color-mint gives you bg-mint, text-mint, border-mint and so on.

/* src/input.css */
@import "tailwindcss";

@theme {
  --color-blush: #FAD4DC;     --color-blush-deep: #A23D60;
  --color-mint: #CDEFE0;      --color-mint-deep: #236B50;
  --color-lavender: #E3DBF8;  --color-lavender-deep: #5E48AE;
  --color-peach: #FDE2CC;     --color-peach-deep: #964C16;
  --color-cloud: #D6EAF8;     --color-cloud-deep: #2A6496;
  --color-butter: #FBF1C7;    --color-butter-deep: #745B06;
  --font-display: "Quicksand", sans-serif;
}
2.8

Dark mode and styling consistency

Add the prefix dark: to any class. It applies only in dark mode. To switch with a button, add one line to input.css so dark mode turns on when a parent has class="dark":

@custom-variant dark (&:where(.dark, .dark *));

Consistency tip: give every element both a light and a dark colour from your tokens, so no text becomes invisible.

2.9

Practical: responsive dashboard or product-listing page

Stat cards: 2 columns on mobile, 4 on large screens. Products: 1 → 2 → 3 columns. Student task: add a 4th product and a dark-mode toggle.

Unit 3

Reusable UI Patterns and Component Design

Stop repeating the same long class lists. Plan and build buttons, cards, forms, modals and more that look the same everywhere.

3.1

Reusable UI patterns and component-based thinking

A component is a small, reusable piece of UI, like a LEGO block. Look at any website and break it into blocks: Navbar, Hero, Card, Button, Footer. Build each block once, then reuse it on every page.

Use case: Flipkart shows hundreds of products, but there is only one product-card design, reused again and again.

3.2

Planning common interface elements for reuse

Before coding, make a component list. For each component, decide its variants (types), sizes and states. This plan keeps the whole website consistent.

3.3

Organizing repeated utility patterns and shared CSS classes

If the same 10 classes repeat on every button, put them into one shared class with @apply inside @layer components. Now class="btn btn-primary" does the whole job.

Rule: use @apply only for things that repeat a lot (buttons, cards, badges). For one-time styling, keep normal utility classes in the HTML.

/* src/input.css */
@layer components {
  .btn {
    @apply inline-flex items-center gap-2 font-bold rounded-full px-5 py-2.5 transition
           focus-visible:ring-4 focus-visible:ring-lavender
           disabled:opacity-50 disabled:cursor-not-allowed;
  }
  .btn-primary   { @apply bg-lavender-deep text-white hover:opacity-90; }
  .btn-secondary { @apply bg-lavender text-lavender-deep; }
  .btn-danger    { @apply bg-blush-deep text-white; }
  .btn-sm { @apply text-xs px-3 py-1.5; }
  .btn-lg { @apply text-lg px-7 py-3.5; }
  .card   { @apply bg-white rounded-2xl shadow-sm border border-lavender/60 p-6; }
  .badge  { @apply inline-block text-xs font-bold px-2.5 py-1 rounded-full; }
}
3.4

Reusable buttons, badges, cards, alerts and content panels

These are the most common building blocks of any website. Build them once and copy the same pattern everywhere.

3.5

Consistent input fields, labels, selects and form layouts

Every input gets the same border, radius, padding and focus ring. Each input has a label. Errors use a red-pink border and a message. The form is 1 column on phones and 2 columns from sm:.

Use case: an admission or registration form.

3.6

Navigation bars, sidebars, modal layouts and dropdowns

  • Sidebar layout: grid with a fixed-width first column from md:; stacked on phones.
  • Dropdown: the HTML <details> tag opens and closes with no JavaScript.
  • Modal: the HTML <dialog> tag. Open with showModal(); Esc closes it automatically.
3.7

Supporting component variants, sizes and visual states

One base class + one variant class + one size class. Mix and match: btn btn-danger btn-lg. States like disabled and loading also look the same everywhere.

3.8

Reusing page sections and separating content from presentation

Content = the data (titles, text). Presentation = how it looks (HTML + classes). Keep them apart: write the card design once in a <template>, keep the data in a JavaScript array, and let a loop make the cards. To add a new card, just add data. No new HTML needed.

Practical: create a small reusable UI pattern collection

Unit 4

HTML Template Reuse, Web Components and Final Project

Make your own HTML tags without React, make pages accessible, test them, and build the final project.

4.1

Reusing shared page sections with template partials

A website has 5 pages, but the header and footer are the same on all of them. Copy-pasting means changing 5 files for every small edit. A partial is one shared piece that you write once and include everywhere.

Way 1: the HTML <template> tag + a little JavaScript (live below). The footer is written once and stamped twice.

Way 2: keep header.html in its own file and load it with fetch(). This needs a local server, e.g. the VS Code Live Server extension.

<div id="header"></div>
<script>
  fetch('partials/header.html')
    .then(res => res.text())
    .then(html => document.getElementById('header').innerHTML = html);
</script>

Way 3: a templating system such as Eleventy (Nunjucks) joins the partials when you build: {% include "header.njk" %}

4.2

Introduction to native Web Components and custom elements

Web Components let you create your own HTML tags, like <hello-badge>, using plain JavaScript and no React. They work in every modern browser.

  • Create a class that extends HTMLElement.
  • connectedCallback() runs when the tag is added to the page.
  • Register it with customElements.define('tag-name', ClassName).
  • The name must have a hyphen (hello-badge ✔, hellobadge ✘).
4.3

Custom elements: attributes, properties and slots

  • Attributes are written in HTML: <user-card name="Riya">. List them in observedAttributes and the component re-draws when they change.
  • Properties are set from JavaScript: card.name = 'Riya'.
  • Slots let the user put their own HTML inside the component. Slots need Shadow DOM.

Two important traps: (1) Tailwind classes do not reach inside Shadow DOM. Use normal light DOM with Tailwind, or add a <style> or <link href="output.css"> inside the shadow root. (2) Never build class names like `bg-${color}`. Tailwind can't find them. Write full class names in a map instead (see tones below).

4.4

Adding JavaScript behaviour to reusable components

Some components need to do something when clicked. Put the behaviour inside the component, so every copy works on its own. Below, each switch remembers its own on/off state, and each counter keeps its own count.

4.5

Accessibility: semantic HTML, labels, keyboard and focus

Accessibility means everyone can use your site, including people who use only a keyboard or a screen reader.

  • Semantic HTML: use <button>, <nav>, <header>, <main>, not <div> for everything.
  • Labels: every input needs a <label for="...">. A placeholder is not a label.
  • Keyboard: everything must work with Tab, Enter and Space.
  • Focus: never remove the focus outline without adding focus-visible:ring-4.
  • Images and contrast: add alt text, and don't put light grey text on white.

Try it: click inside the example, then press Tab. The "bad" div button is skipped; the good button gets a clear ring.

4.6

Responsive testing, browser checks and common UI troubleshooting

How to test: open Chrome DevTools (F12), click the device icon (Ctrl + Shift + M) and check widths 360px (phone), 768px (tablet) and 1280px (laptop). Also test in a second browser (Firefox or Edge), zoom to 200%, and run a Lighthouse report.

4.7

Component organization, naming conventions and maintainability

A clean folder structure and clear names help you (and your team) find and fix things quickly.

my-project/
├── package.json
└── src/
    ├── index.html
    ├── about.html
    ├── input.css            (@theme tokens + @layer components)
    ├── output.css           (built file, don't edit)
    ├── partials/
    │   ├── header.html
    │   └── footer.html
    └── components/
        ├── user-card.js
        ├── toggle-switch.js
        └── info-box.js
RuleExample
Custom element names: lowercase with a hyphenuser-card, toggle-switch
JS class names: PascalCase, same name as the tagUserCard, ToggleSwitch

Tokens named by meaning, not just colour--color-primary, --color-danger
Keep classes in the same order on every elementlayout → spacing → colour → text → states

Practical project: responsive website with reusable UI

Build a 3–4 page website on one topic: college fest, café, portfolio, gym, book store or travel agency.

Must have

  • Tailwind CLI setup (not CDN)
  • Own colour and font tokens in @theme
  • Works at 360px, 768px and 1280px
  • Shared header and footer (partials)
  • Dark mode toggle

Components

  • At least 6 reusable patterns (button, card, badge, alert, form, modal…)
  • At least 2 Web Components
  • Cards made from data (3.8)
  • Accessible form with labels and focus rings
  • Lighthouse accessibility score of 90+
